# To be extracted!

The plan is to extract the content of this file into a new npm package `@hawk-hhg/hawki-svelte-components`. Which is why it already lives in this namespace in our tsconfig paths. Extraction means, that all componenents in this directory MUST be self-contained and not depend on any other part of the HAWKI codebase. This is a hard requirement, because the new package will be published to npm and consumed by other projects.

## Import rules

- **Inside this directory**: always use relative imports (`./`, `../`). Never import
  from `$lib/...`, `$plugins/...`, or from the alias itself — the latter would be
  circular.
- **Outside this directory**: import from the bare specifier
  `@hawk-hhg/hawki-svelte-components`, which resolves to `index.ts`.
- **Icons** are the one exception. `ui/icons/iconset/` holds ~6.1k generated
  components and is deliberately *not* re-exported from the barrel — that would
  force every consumer to pull in the whole set. Import them by subpath:
  `@hawk-hhg/hawki-svelte-components/ui/icons/iconset/Cancel01Icon.svelte`.
  These files are generated by `vitePluginHugeicons`; never edit them by hand.
- `util/breakpoints/breakpoints.ts` is generated by `vitePluginBreakpoints` from
  `resources/css/tokens/breakpoints.css`. Change the generator in
  `.vite/vitePluginBreakpoints.ts`, not the output.

## Constraints worth knowing

**Public types cannot live in `<script module>`.** `svelte-check` resolves
`.svelte` files properly, but plain `tsc` falls back to Svelte's ambient
`declare module '*.svelte'`, which carries only a default export. A `.ts` barrel
therefore cannot re-export anything declared in a module script. Anything that
should be public API needs a sibling `.ts` file (see `ui/button/variants.ts`,
`ui/select/types.ts`).

**A type and a component cannot share a name in the barrel.** TypeScript rejects
it with `Duplicate identifier`. This is why the breakpoint union is called
`BreakpointName` while the component is `Breakpoint`.

**Contexts must be provided at every mount root.** The app mounts Svelte in more
than one place: `Shell.svelte` (via `ShellExtension`) *and* `legacy/svelteSnippetLoader.ts`,
which mounts each `<svelte-snippet>` as its own independent root. A context set in
`Shell.svelte` is invisible to those legacy islands. Any service this package
consumes via context must be provided at **both** roots, or components silently
fall back to their defaults inside legacy UI — with no build or type error to
warn you.

Both roots are wired through the single helper `app/provideComponentServices.ts`:
`Shell.svelte` calls it directly, and `legacy/SnippetServicesProvider.svelte`
wraps every legacy snippet root. **Add new services there**, not at the call sites.

**Inject getters, not values.** A context is created once at mount. Passing
`themeStore.theme` would freeze the value at that instant; passing
`() => themeStore.theme` keeps `$derived` consumers tracking the host's live
state. Same applies to any future reactive service.

## Dependency-injection design

The package never reaches into the host app. Anything it needs from outside is
injected at the root as an optional service with a working default, so the
components still render standalone:

| Contract | Injected by host | Default when absent |
|---|---|---|
| `TranslatorInterface` | app's i18n translator | identity — returns the key |
| `LinkServices.faviconUrl` | `app.uriBuilder.linkPreviewFaviconUri` | no favicon rendered |
| `LinkServices.fetchPreview` | `app.linkPreviewApi` | no preview rendered |
| `ColorSchemeContext` | `ThemeStore.theme` | `'light'` |

Translation keys owned by this package are namespaced (`components.*`) so they
cannot collide with host application keys. In HAWKI they live in
`resources/language/components_{locale}.json`, which needs its own top-level
`components` key: `TranslationFileLoader` merges every `*_{locale}.json` with a
shallow top-level merge, so two files sharing a top-level key silently clobber
each other.
